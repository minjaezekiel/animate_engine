jireX workspace

A browser animation engine: 2D films from a screenplay, 3D films from a declarative script, drawn animation, voices, and deterministic rendering to MP4.

Everything below is grouped by what you are trying to do, not by which file it lives in.

npm install  ·  npm run serve  ·  open http://localhost:8080/workspace.html

Make

Four editors. They are separate programs with similar names, so each one says here what it is for — pick by the sentence, not the title.

Film Studio 2D

Author a film as a screenplay or a film.json, cast voices, preview it, and export MP4 or WebM. The surface most finished work in this repo came out of.

Pose Editor 2D

Drag a character's joints directly and scrub the timeline. For getting a pose right when typing degrees is not working.

Draw 2D

Freehand and trace, on an exposure sheet, with time-gated smears and boil. For animation that should look drawn rather than tweened.

3D Editor legacy

Primitives, lights, PBR materials, skeletons, keyframes and physics, in a single-file Three.js editor. Still the only interactive 3D surface — a 3D film is authored as a document and rendered headless.

Check

Run these before spending a render. All of them are seconds, none of them encodes anything, and between them they catch most of what a finished film would have shown you ten minutes later.

Each answers a different question, and only the last one costs real tokens.
CommandAnswers
npm run check:earth Compiler diagnostics, framing measured by projecting each subject's bounds through the camera, exposure from real pixels at 160×90, and the overlay checked over its own draw list.
DIGEST=1 node scripts/produce3d.mjs What is on screen, as numbers. Per subject: screen box, frame coverage, mean luma, dominant hue — plus every string of overlay text. About 400 tokens for a whole film against roughly 2,000 for one screenshot.
node scripts/check-film.mjs The 2D equivalent: compile, validate, stage and budget, no render.
npm run tex earth:albedo Paints a procedural texture to a PNG in Node, with no browser, so a seam or a clipped ramp can be seen in under a second.
npm run pacing Speech as a fraction of runtime, against measured references.
GRAB=12,40.3 node scripts/produce3d.mjs Rendered frames as PNGs. The only check that catches a model not looking like the thing it is meant to be — and the one to reach for last.

Render

Rendering is a terminal job on both paths: it needs a real browser for WebGL, WebCodecs and the TTS worker, and it takes a lock so two of them cannot fight over memory.

2D film

FILM=demo/film.json OUT=out/film.mp4 \ npm run produce

H.264/AAC through WebCodecs, faster than real time. FORMAT=webm for the zero-dependency paced path.

3D film mp4

FILM=films/earth3d.json OUT=out/earth.mp4 \ npm run produce:3d

Same encoder, same container, same chunked readback. Textures, cutaways, subtitles, callouts and the post chain all come from the one document.

Voices

Four engines behind one gateway. A film casts by role (narrator-m-en), never by model id, so the same document renders offline on Piper and on a cloned voice when one is configured. VOICE_BACKEND=<name> promotes one without removing the safety net.

Build a film

The 3D path end to end, as it actually runs. Each step is cheap until the last one.

npm run make:earth-audio # synthesize the score and effects npm run make:earth # write films/earth3d.json from the generator npm run check:earth # compile, framing, exposure, overlay — seconds DIGEST=1 FILM=films/earth3d.json node scripts/produce3d.mjs # what is on screen, as numbers GRAB=3,22,36 FILM=films/earth3d.json node scripts/produce3d.mjs # look at three frames npm run render:earth # 1920×1080 H.264/AAC node scripts/verify-renders.mjs out/earth/inside-the-earth.mp4

Known limits

The honest list for the 3D path, kept here rather than only in the docs because a limit you find out about after a render is worse than one you read first. Full detail in docs/completed_phases/34-EARTH-3D.md.

LimitWhat it costs
No modelling toolEvery 3D form is typed as numbers, rendered, and looked at. There is no viewport, no vertex editing, no sculpting.
Post is not keyframeableOne focal plane for the whole film. No rack focus, no exposure ramp, no bloom that builds.
No day/night maskAn emissive map glows on the lit side too, so city lights have to be dialled down until they are invisible by day.
Particles cannot collideInherent to solving them in closed form, which is also what makes them seekable.
No per-object motion blurParticles stretch by velocity; meshes do not.
No action dependenciesNothing can say "start when that lands". Both are timed against the same clock and nothing checks they agree.
Clothing is an inflated bodyNo drape, no folds, no collar. The cloth solver drapes a cape, not a sleeve.
